# 无公式通报模板映射与计算需求

Feature Name: formula-driven-notice-mapping
Updated: 2026-08-19

## 1. Introduction

系统需要支持无公式通报模板。系统通过模板列映射、基础数据字段映射、指标计算规则和结果校验生成完整通报页，并保留模板的布局、样式、合并区域和明细 Sheet。

本需求以 `.monkeycode-tmp-files/53434fe4-模版+明细-2.xlsx` 为样例。样例包含 `模版` 和 `明细` 两个 Sheet：通报页为 12 列、21 行，明细页第 3 行为字段表头，数据从第 4 行开始，共 55 个字段。

## 2. Glossary

- **通报列**：`模版` Sheet 中用于展示日期、单位、目标、数量、完成率、排名和分产品指标的列。
- **明细字段**：`明细` Sheet 第 3 行定义的基础数据字段。
- **维度字段**：用于分组、筛选或匹配的字段，例如组织、日期、业务类型。
- **指标字段**：参与求和、计数、比率或排名计算的字段，例如 `W=百元等效值`。
- **指标规则**：定义指标来源、聚合方式、过滤条件、分母和空值处理的可版本化配置。
- **列映射**：通报列与明细字段、常量或指标规则之间的绑定关系。
- **公式处理**：在生成阶段计算值，或在生成的 Excel 中写入可重算公式的过程。
- **模板版本契约**：模板版本对应的 Sheet、列位置、表头、维度、指标和规则集合。

## 3. Sample Mapping Baseline

系统 SHALL 将以下内容作为样例模板的初始候选映射，并要求用户确认后才能生效：

| 通报语义 | 模板位置 | 候选来源 | 处理方式 |
|---|---|---|---|
| 日期 | `模版!A3` | `明细!A` `DAY_ID` | 取数据源最大日期或配置日期，格式化为通报日期 |
| 天数 | `模版!B3` | 日期配置 | 取日期的日号，或按周期配置计算 |
| 单位名称 | `模版!B5:B20` | 模板原值 | 作为模板维度，不从明细自动覆盖 |
| 单位简称 | `模版!C5:C20` | 模板原值 | 作为模板维度，不从明细自动覆盖 |
| 目标值 | `模版!D5:D20` | 模板原值 | 作为模板参数，不从明细自动覆盖 |
| 组织筛选字段 | 通报单位行 | `明细!H` `收入归属区县名称` | 按单位全称匹配 |
| 基础指标 | `模版!E5:E20` | `明细!W` `百元等效值` | 按组织、日期和产品条件聚合 |
| 产品筛选字段 | 分产品指标 | `明细!C` `业务类型` | 通过产品条件配置筛选 |
| 原数量 | `模版!G5:G20` | `明细!W` | 由数量指标规则定义，禁止凭列名自动确定 |
| 最终数量 | `模版!H5:H20` | 指标规则 | 由业务确认的聚合或转换规则计算 |
| 日完成率 | `模版!F5:F20` | `E / D` | 分母为 0 时按规则返回空值或 0 |
| 序时完成率 | `模版!I5:I20` | 目标与周期参数 | 需要用户确认周期目标和已过天数口径 |
| 排名 | `模版!J5:J20` | 完成率或指标值 | 排名方向、并列规则和范围必须配置 |
| 分产品日/月 | `模版!K5:L20` | `明细!C` + `明细!W` | 产品条件、日周期和月周期分别配置 |

系统 SHALL 将 `明细!BA`（`下沉区县名称`）作为组织维度的高优先级候选字段。`明细!AZ`（`下沉规则`）当前样本值为“发展人”，属于筛选规则字段，系统 SHALL 将其作为条件字段候选保存。

带公式副本确认的样例口径如下：

- `E`：按 `BA` 汇总 `W`，同时按 `B=模版!A3` 筛选当日数据。
- `F`：`E/(D/31)`。
- `G`：按 `BA` 汇总 `W`，覆盖整月数据。
- `H`：按 `BA` 汇总 `W`，覆盖整月数据。
- `I`：`G/(D*B3/31)`，其中 `B3` 为通报日期日号。
- `J`：按 `I` 排名，且存在两个排名区间 `I5:I15` 与 `I16:I20`。
- `K`：按 `BA`、当日 `B=A3` 和 `C=升档专用合约` 汇总 `W`。
- `L`：按 `BA` 和 `C=升档专用合约` 汇总 `W`，覆盖整月数据。
- `AZ` 未出现在带公式副本的通报公式中，系统 SHALL 将其保留为可选规则条件，不自动追加到公式。

## 4. Requirements

### Requirement 1: Template Contract

**User Story:** 作为模板管理员，我希望为无公式模板定义版本契约，以便模板位置变化时仍能稳定生成。

#### Acceptance Criteria

1. WHEN 用户分析无公式模板，系统 SHALL 识别通报 Sheet、明细 Sheet、表头行、数据起始行、合并区域、模板参数区和候选输出列。
2. WHEN 模板列存在表头，系统 SHALL 为每个通报列保存 Sheet、地址、表头、列类型、样式摘要和是否允许覆盖。
3. WHEN 模板版本发生变化，系统 SHALL 创建独立的模板版本契约并保留历史规则。
4. IF 通报列缺少来源规则，系统 SHALL 将列标记为待配置并阻止生成。

### Requirement 2: Dimension Mapping

**User Story:** 作为业务人员，我希望把通报单位行与基础数据组织字段绑定，以便每个单位行获得正确的统计结果。

#### Acceptance Criteria

1. WHEN 用户配置组织维度，系统 SHALL 支持模板单位名称、模板简称与明细字段值的独立匹配。
2. WHEN 组织名称存在全称、简称或别名差异，系统 SHALL 支持别名表和规范化匹配，并显示匹配结果。
3. WHEN 一个模板单位匹配多个明细值，系统 SHALL 要求用户确认聚合范围。
4. IF 模板单位没有匹配数据，系统 SHALL 显示 0 行、空值或业务配置结果，并在生成预检中提示。

### Requirement 3: Metric Rules

**User Story:** 作为业务人员，我希望按业务口径配置每个通报指标，以便无公式模板生成正确的数量、完成率、月累计和分产品数据。

#### Acceptance Criteria

1. WHEN 用户创建指标规则，系统 SHALL 要求配置指标名称、聚合方式、来源字段、分组维度、过滤条件、周期范围、空值策略和结果类型。
2. WHEN 聚合方式为 `sum`、`count`、`count_distinct`、`avg` 或 `max`，系统 SHALL 使用对应方式计算指标。
3. WHEN 指标包含产品条件，系统 SHALL 保存产品字段、条件值和条件版本。
4. WHEN 指标为比率，系统 SHALL 保存分子指标、分母指标、零分母处理和精度规则。
5. WHEN 指标为排名，系统 SHALL 保存排名输入指标、排序方向、并列策略和排名范围。
6. IF 指标来源字段缺失、类型不兼容或条件无效，系统 SHALL 阻止生成并定位到具体规则。

### Requirement 4: Formula Execution

**User Story:** 作为业务人员，我希望生成结果同时支持稳定计算和 Excel 可复核公式，以便检查通报口径。

#### Acceptance Criteria

1. WHEN 规则选择值计算模式，系统 SHALL 在后端计算结果并将结果值写入通报页。
2. WHEN 规则选择 Excel 公式模式，系统 SHALL 写入结构化公式、保存公式依赖和设置 Excel 自动重算标记。
3. WHEN 公式模式需要跨 Sheet 聚合，系统 SHALL 根据字段映射生成可读的 `SUMIFS`、`COUNTIFS` 或等价公式，并保存公式模板。
4. WHEN 公式模式使用动态数据范围，系统 SHALL 使用 Excel Table 或 profile 定义的动态范围。
5. IF 当前运行环境无法计算 Excel 公式缓存，系统 SHALL 明确标记“待 Excel 重算”，并提供值计算模式作为可选执行策略。

### Requirement 5: Column Mapping UI

**User Story:** 作为模板管理员，我希望以通报列为主线配置来源和指标，以便快速理解每一列的业务含义。

#### Acceptance Criteria

1. WHEN 用户打开映射中心，系统 SHALL 按 Sheet、通报区域和列顺序展示所有可配置通报列。
2. WHEN 用户选择通报列，系统 SHALL 展示候选明细字段、字段样例、类型、质量状态、指标规则和依赖关系。
3. WHEN 用户选择直接字段、指标、公式、常量或模板保留值，系统 SHALL 展示对应的配置表单。
4. WHEN 用户保存映射，系统 SHALL 创建不可变规则版本并显示预检摘要。
5. IF 映射存在缺失、冲突、循环依赖或模板公式覆盖风险，系统 SHALL 禁止发布该规则版本。

### Requirement 6: Generation Validation

**User Story:** 作为生成操作人员，我希望系统在生成前验证数据和口径，以便避免生成空通报或错位通报。

#### Acceptance Criteria

1. WHEN 用户选择数据源和工作流，系统 SHALL 校验字段签名、日期覆盖、组织覆盖、产品条件和指标字段质量。
2. WHEN 预检完成，系统 SHALL 展示每个通报区域的匹配行数、指标计算状态、缺失组织、缺失产品和公式状态。
3. IF 关键字段缺失、目标行无法匹配或指标规则未确认，系统 SHALL 阻止生成。
4. WHEN 生成成功，系统 SHALL 保存模板版本、映射版本、规则版本、数据指纹和计算引擎。

### Requirement 7: Workbook Integrity

**User Story:** 作为结果使用人员，我希望成品保持模板原生结构，以便直接打印和继续审阅。

#### Acceptance Criteria

1. WHEN 系统生成成品，系统 SHALL 保留 `模版` 和 `明细` Sheet 名称、顺序、合并区域、样式、列宽、行高和页面设置。
2. WHEN 系统写入通报列，系统 SHALL 仅覆盖映射允许覆盖的单元格。
3. WHEN 数据行超过模板已有明细行，系统 SHALL 复制样式来源行并更新明细范围。
4. WHEN 生成完成，系统 SHALL 校验通报列数量、公式引用、结果类型和工作簿可打开性。

## 5. Open Business Decisions

以下内容需要业务确认后固化为默认规则：

1. `原数量`、`最终数量`与`百元等效值`之间的计算口径。
2. `序时完成率`的周期总天数、已过天数和目标基准。
3. `升档专用合约`的精确过滤条件，是否使用 `业务类型=升档专用合约`。
4. 组织维度使用 `收入归属区县名称(H)`、`收入归属渠道区县名称(AG)` 或其他字段。
5. “日”与“月”的日期范围，是否按 `DAY_ID(A)`、`受理时间(B)` 或其他日期字段。
6. 排名按日完成率、月完成率、最终数量还是其他指标排序。
